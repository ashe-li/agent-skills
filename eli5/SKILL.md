# /eli5 — 白話解釋

把「$ARGUMENTS」講給一個聰明、但完全沒接觸過這個領域的人聽。對象不是真的五歲小孩：不裝可愛、不用疊字，只是**假設對方零背景知識**。

> 來源：Anthropic 員工 Thariq Shihipar 分享的 `/eli5`（`anthropics/claude-plugins-community`），原版只有一句話——「像對完全不懂這個主題的人解釋，用一個大圖少字的 HTML artifact」。本 skill 保留那句話的精神，加上繁體中文的觸發語，並多一個不用開頁面的對話版。

## Step 0：定主題、定模式

- **主題**：`$ARGUMENTS` 有值就用它；空的就是上一則回覆、或使用者正指著的那個東西（一個 alert、一段 log、一個剛修好的 bug）。主題不明確時問一句「你是指 X 還是 Y？」，不要猜。
- **模式**：

| 使用者怎麼說 | 模式 |
| :-- | :-- |
| 「白話解釋」「我看不懂」「X 是什麼」「用比喻講」（對話中順口問） | **對話版**（預設） |
| `/eli5 <主題>`、「圖解」「畫給我看」「做成一頁」「做個 explainer」 | **圖解版**（HTML 頁） |
| 對話版講完後追問「畫成圖」 | 升級成圖解版，沿用同一組類比 |

## 對話版（預設）

固定四段，順序不變：

1. **一句話類比**：先講「它像什麼」，再講「為什麼要有它」。用生活場景（郵局、水管、餐廳點餐、礦坑金絲雀、舀一杯水驗水質），不用另一個技術概念當比喻。
2. **要點 3–5 條**：每條一句話。術語第一次出現時，括號內用白話補一句（例：「cache（先把答案抄一份放手邊，下次不用重算）」）。
3. **類比在哪裡失效**：一句話。每個類比都有講不通的地方，先講出來，免得使用者拿類比去推出錯的結論。
4. **技術細節（可選）**：使用者追問、或這個概念本來就得靠細節才成立時才展開；否則停在第 3 段。

規則：

- **簡單的東西直接講重點**，不硬套類比。一句話能講清楚的，類比反而是干擾。
- **五歲測試**：每一句都問「這句能對完全不懂的人講出來嗎？」出現沒解釋的術語就是失敗，回頭補括號或換說法。
- **簡化是省略，不是改事實**。為了好懂而跳過的地方，加一句「這裡省略了 X」，不要把不完整講成完整。
- **不知道就說不知道**：主題超出掌握範圍時明講「這部分我不確定」，不用類比把不確定包裝成確定。
- 類比與要點合計控制在 200 字上下；技術細節另起一段，讓使用者可以不看。
- 繁體中文、台灣用語；技術術語保留英文原詞不硬翻；不用 emoji。
- 解釋的是「剛做完的事」（修了一個 bug、改了一個 alert、動了一個 config）時，四段改成：**發生了什麼 → 為什麼會這樣 → 我做了什麼 → 你接下來要注意什麼**。

## 圖解版（`/eli5` 或「圖解」）

忠於原版：**一頁 HTML，大圖、極少文字**。圖是主角，文字只是圖說。

結構：

- 3–6 個「畫面」（scene），從上往下捲。每個畫面 = 一張 inline SVG 示意圖 + 標題（≤ 10 字）+ 說明（≤ 2 句）。
- 第一個畫面就是類比；最後一個畫面是「一句話帶走」。
- SVG 只用簡單形狀、箭頭、標籤把機制畫出來（誰送什麼給誰、資料從哪流到哪、哪一步會卡）。不放表格、不放程式碼、不放超過 15 個字的文字塊。
- 標題與圖說不出現「白話」「人話版」這類 label；頁面標題就是主題本身。

技術要求：自包含（inline CSS 與 SVG，不載外部資源）、手機寬度也能讀、深淺色主題都看得清。

交付方式（依環境二選一）：

1. 有 `Artifact` 工具 → 依該工具規定先載入 `artifact-design` skill，把頁面寫到 scratchpad（`eli5-<主題-slug>.html`）再 publish，回連結。
2. 沒有 `Artifact` 工具 → 寫到專案的 `.eli5/<主題-slug>.html`，`open` 它，回路徑。

不論哪一種，對話裡都附 3 行文字摘要（類比一句、機制一句、帶走一句），讓不開頁面的人也看得懂。

## 交付前自檢

- 五歲測試過了：沒有未解釋的術語。
- 類比失效點有標出來。
- 簡化的地方沒有講錯；省略處有提。
- 會被外部讀者看到的產物（頁面標題、檔名、section heading）沒有「白話」「人話版」字樣。

## 邊界

- **不是 speak-human-tw**：那個是拿一段既有文字去 AI 味、校台灣用語；本 skill 是把一個「東西」講懂。使用者手上有稿子要改 → speak-human-tw；使用者想聽懂某個東西 → 本 skill。
- **對外／跨團隊文件**：本 skill 的產物是給發問者看的；要進對外文件時，類比與示意圖可以搬，但標題與 section 用「概覽」「設計概覽」「類比」等中性詞，不掛「白話」label。
- **不取代完整規格**：使用者要 spec、要程式碼、要 runbook 時，直接給那個，不先繞一輪類比。
